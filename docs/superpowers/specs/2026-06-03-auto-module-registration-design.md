# Design : Auto-enregistrement des modules & `helix run` zéro-configuration

**Date :** 2026-06-03  
**Statut :** Approuvé

---

## Problème

Après `helix generate module order`, le développeur doit manuellement :
1. Importer `"my-api/orders"` dans `main.go`
2. Ajouter `&orders.OrderRepository{}`, `&orders.OrderService{}`, `&orders.OrderController{}` à la slice `Components`

Cela casse le flux zéro-boilerplate promis par Helix et force une modification de `main.go` pour chaque nouveau module.

---

## Solution

Trois changements coordonnés :

1. **Nouvelle API framework** : `helix.RegisterComponents(components ...any)`
2. **Nouveau fichier généré par module** : `<module>/register.go` avec un `init()` qui appelle `RegisterComponents`
3. **Nouveau fichier généré global** : `cmd/helix_imports_gen.go` avec des blank imports pour déclencher les `init()`

`helix run` appelle déjà `helix generate` avant chaque build — aucun changement nécessaire au runner.

---

## Architecture

### 1. API framework — `helix.RegisterComponents`

**Fichier :** `helix.go` (ou nouveau `components.go`)

```go
var (
    componentsMu   sync.Mutex
    autoComponents []any
)

// RegisterComponents enregistre des composants pour auto-wiring lors du
// prochain appel à helix.Run(). Destiné aux init() générés par helix generate.
func RegisterComponents(components ...any) {
    componentsMu.Lock()
    defer componentsMu.Unlock()
    autoComponents = append(autoComponents, components...)
}
```

**Intégration dans `runAutoBootstrap`** : avant de passer à `runWithApp`, fusionner `autoComponents` dans `app.Components` :

```go
func runAutoBootstrap(base App) error {
    componentsMu.Lock()
    collected := append([]any(nil), autoComponents...)
    componentsMu.Unlock()
    base.Components = append(base.Components, collected...)
    // ... suite inchangée
}
```

Le state global (`autoComponents`) est acceptable : il suit le précédent établi par `wireSetupFn` et `webSetupFn`. Il n'est consommé qu'une seule fois au démarrage.

### 2. Fichier généré par module — `register.go`

Généré par `helix generate module <name>` et `helix generate context <name>`.

**Exemple pour `helix generate module order` :**

```go
// Code generated by helix; DO NOT EDIT.
package orders

import "github.com/enokdev/helix"

func init() {
    helix.RegisterComponents(
        &OrderRepository{},
        &OrderService{},
        &OrderController{},
    )
}
```

**Règles :**
- Nom du fichier : `register.go` (pas `_gen.go` pour éviter d'être exclu par `isScannableGoFile`)
- Marqueur en tête : `// Code generated by helix; DO NOT EDIT.`
- Contient uniquement l'`init()` — pas de logique applicative

### 3. Fichier généré global — `cmd/helix_imports_gen.go`

Généré/regénéré par `helix generate` (scan complet).

**Algorithme de génération :**
1. Lire `go.mod` pour obtenir le module path (ex: `my-api`)
2. Scanner récursivement tous les sous-répertoires pour trouver les fichiers `register.go` contenant `// Code generated by helix`
3. Pour chaque package trouvé, construire le chemin d'import : `<module-path>/<folder>`
4. Écrire `cmd/helix_imports_gen.go` avec les blank imports triés
5. Si aucun package trouvé : ne pas écrire le fichier (ou écrire un fichier vide sans imports)

**Exemple de fichier généré :**

```go
// Code generated by helix; DO NOT EDIT.
package main

import (
    _ "my-api/billings"
    _ "my-api/orders"
    _ "my-api/products"
)
```

**Localisation :** `cmd/` si ce répertoire existe et contient `main.go`, sinon à la racine du projet (là où `main.go` est trouvé).

### 4. `main.go` — inchangé

Le template généré par `helix new` reste :

```go
func main() {
    if err := helix.Run(); err != nil {
        log.Fatal(err)
    }
}
```

Aucune modification requise pour ajouter un module.

## Flux développeur après implémentation

```bash
# Créer le projet
helix new my-api
cd my-api

# Ajouter un module
helix generate module order
# Crée: orders/repository.go, orders/service.go, orders/controller.go, orders/register.go

# Lancer l'application (génère helix_imports_gen.go + build + run)
helix run
# → helix generate détecte orders/register.go
# → génère cmd/helix_imports_gen.go avec _ "my-api/orders"
# → build → run
# → orders.OrderRepository, OrderService, OrderController auto-wirés
```

## Changements de code

| Fichier | Type | Description |
|---------|------|-------------|
| `helix.go` | Modifié | Ajouter `RegisterComponents`, `autoComponents`, fusion dans `runAutoBootstrap` |
| `cli/internal/scaffold/scaffold.go` | Modifié | `GenerateModule` et `GenerateContext` génèrent aussi `register.go` |
| `cli/internal/scaffold/templates.go` | Modifié | Nouveau template `registerTemplate` |
| `cli/internal/codegen/generator.go` | Modifié | Après génération des packages, générer `cmd/helix_imports_gen.go` |
| `cli/internal/codegen/scanner.go` | Modifié (ou nouveau) | Scanner pour trouver les `register.go` générés |

## Gestion des cas limites

- **Module supprimé** : à la prochaine `helix generate`, son import disparaît de `helix_imports_gen.go`. Le build échoue si le répertoire est supprimé sans regénérer — comportement normal pour un fichier généré.
- **Projet existant sans `register.go`** : `helix_imports_gen.go` n'est pas généré (aucun module détecté). L'enregistrement manuel via `Components: []any{...}` continue de fonctionner.
- **Double enregistrement** : si un composant est à la fois dans `autoComponents` et dans `app.Components`, le container doit gérer l'idempotence (comportement existant à vérifier).
- **`helix generate` sans `cmd/`** : chercher `main.go` à la racine du projet comme fallback.

## Documentation à mettre à jour

Les fichiers suivants décrivent le flux d'enregistrement manuel et doivent être mis à jour pour refléter l'auto-enregistrement.

### `docs/reference/cli.md` et `docs/fr/reference/cli.md`

**Section `helix generate module`** — remplacer le bloc "After generating, register the components in `main.go`" par :

> Les composants sont enregistrés automatiquement. Aucune modification de `main.go` n'est requise.

Mettre à jour la structure de fichiers générés pour inclure `register.go` :

```
orders/
├── controller.go
├── service.go
├── repository.go
└── register.go   # auto-enregistrement via init()
```

**Section `helix generate context`** — même mise à jour (ajouter `register.go` dans la structure, supprimer le bloc d'enregistrement manuel).

**Section `helix run`** — ajouter une note :

> `helix run` appelle automatiquement `helix generate` avant chaque build. Cela régénère `cmd/helix_imports_gen.go` pour inclure tout nouveau module détecté.

### `docs/guide/cli.md` et `docs/fr/guide/cli.md`

- Supprimer le bloc `Components: []any{...}` dans les exemples post-génération de module
- Remplacer par : "Les composants sont auto-détectés et enregistrés. Lancez `helix run` directement."

### `docs/guide/quick-start.md` et `docs/fr/guide/quick-start.md`

- Si le quick-start montre une étape d'enregistrement manuel, la supprimer ou la marquer comme optionnelle (uniquement pour les projets sans CLI).
